# 09-07-2026

**HARBOR TAG IMMUTABILITY VS RETENTION**

Set a tag retention policy to keep "only the last 10 tags" on a repo that also had tag immutability enabled, and deployments started failing with a confusing permission-looking error. Immutable tags can't be deleted by definition - so the retention policy's cleanup job was silently failing to enforce itself against tags it wasn't allowed to touch.

The two features aren't meant to be layered carelessly: immutability is for release tags you never want rewritten or removed; retention is for cleaning up the noise (like `latest`-style dev builds) that should never have been marked immutable in the first place.
