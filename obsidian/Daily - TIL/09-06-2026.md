# 09-06-2026

**ANSIBLE: COMMAND VS SHELL**

Reached for `shell` out of habit in a new role and it broke idempotency checking - Ansible can't tell if a raw shell pipeline actually changed anything, so it reports `changed` every single run, which then trips up anyone relying on `changed_when` downstream.

`command` doesn't support pipes or redirects, but for anything that does need a shell, wrapping the actual check in `changed_when` (or reaching for the dedicated module - `copy`, `lineinfile`, whatever exists) gets idempotency back. Rule of thumb now: `shell` is for one-offs, not for anything a report depends on.
