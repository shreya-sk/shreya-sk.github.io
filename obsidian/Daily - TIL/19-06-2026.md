# 19-06-2026

**HELM --DRY-RUN BLIND SPOT**

`helm install --dry-run` renders the templates but doesn't hit the Kubernetes API server for validation - so it happily renders a Deployment with a typo'd `apiVersion` or a field that doesn't exist on the real cluster's CRD version, and you don't find out until the real install.

`--dry-run=server` actually submits to the API server without persisting, which catches this class of bug. Costs a few more seconds; worth it before anything touching a CRD.
